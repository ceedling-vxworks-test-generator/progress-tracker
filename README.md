# progress-tracker

プロジェクトメンバーの進捗管理用ツール。まずは Excel で試作し、要件が固まった段階で Web アプリ化を検討する想定です。

## 背景・課題

- プロジェクトメンバーの進捗管理を行いたいが、許可されているツールで容易に管理できるものがなく、マイルストーンに対しての残タスク管理がしづらい。
- 現状は Excel と Teams の作業トラッカーを連携させて運用しているが、不便。

## このリポジトリの内容

`progress_tracker.xlsx` — 進捗管理用の Excel テンプレート(サンプルデータ入り)。

タスクの先行関係(依存関係)と所要日数から、各タスクの計画開始日・終了日・クリティカルパスを数式で自動計算します。VBA・マクロなし(数式のみ)なので、マクロを許可していない環境でもそのまま使えます。

対応している項目:

- 作業者ごとの残タスク数の把握(ダッシュボードシート + オートフィルタ)
- マイルストーンごとの残タスク数・進捗率の把握
- 残タスクのクリティカルパスの自動判定
- 残タスクが何の先行タスクに影響されて止まっているかの自動表示(ブロック要因)
- 計画開始日・計画終了日の自動計算(先行タスクの終了日 + 所要日数から逆算)
- タスクの追加・削除・更新(行の追加/編集のみ)
- 親タスクID によるサブタスクのグルーピング表示(簡易対応)
- ガントチャート(線表)による可視化。クリティカルパス上のタスクは赤、それ以外は青で表示(「ガントチャート」シート、タスク一覧の先頭20件が対象)

詳しい使い方はファイルを開いて「使い方」シートを参照してください。

## 既知の制約

- 先行タスクは、そのタスクより上の行に入力する必要があります(数式が正しく計算されるための前提条件)。
- 先行タスクは最大3件まで(4件以上必要な場合はダミーの中間タスクを挟んでください)。
- ガントチャートは「タスク一覧」の先頭20行のみ対象です(それ以降のタスクは表示されません)。横軸は実際の日付ですが、表示範囲(軸の最小値/最大値)はサンプルのプロジェクト期間に合わせて固定されています。「設定」シートのプロジェクト開始日を大きく変更した場合は、グラフの縦軸を右クリック→「軸の書式設定」で最小値/最大値を調整してください。
- 親タスクID はグルーピング表示のためだけの項目で、日程計算には使われません(サブタスク自体の日程を自動計算したい場合は、そのサブタスクにも先行タスクを設定してください)。
- 祝日は考慮していません(土日のみ除外)。祝日を考慮したい場合は WORKDAY/NETWORKDAYS 関数に祝日リストを追加してください。

## 今後について

Excel での運用を通じて要件を検証したうえで、必要であれば Web アプリ化(ブラウザから使える社内ツール化)を検討します。
